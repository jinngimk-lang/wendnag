# AragonTeam Company Product OS — 市场版交互设计节点

Date: 2026-09-20

## 用户目标
用户希望把 AragonTeam 逐步沉淀为一套“企业产品操作系统 / Company Product OS”的产品语言：未来新增项目管理、市场、销售、法务等模块时，不重新发明交互与 UI；用户熟悉任一模块后约 20 分钟即可迁移使用其它模块。

## 已确认的 Company Product OS 原则
- 公司级一致性优先于单模块局部最优。
- Standardize the solved. Preserve the identity. Maximize the new.
- 人与 Agent 共同维护产品/项目本体；Agent 能提出、分析、执行低风险变更，人可检查、干预、审批、回滚。
- AI Presence / Agent 不只是聊天框，而是贯穿界面的“协作者”：理解意图、打开工具、修改状态、展示执行过程、汇报结果。
- 每个业务模块应复用同一套对象、状态、动作、审批、时间线、证据、复盘语义。
- 结构化 UI 是事实与状态的真相层；自然语言是低门槛控制面。Agent 把自然语言翻译成结构化变更，并在必要时先展示变更预览。

## 当前市场版痛点
现有页面能力很全，但模块过度平铺：市场总览、市场任务、客户作战室、商机管道、行动中心、活动与样机、作战手册、复盘中心、市场战役、市场看板、市场需求等需要用户自己拼接，认知成本过高。

## 已确认的目标交互主线
保留“客户列表与机会总览 → 客户详情与阶段流程 → Agent 建议 → 话术/内容 → 互动记录 → 复盘”的总体逻辑。

将市场版的核心操作收敛为：
1. 选择客户
2. 客户洞察 / 评分 / Why Now
3. 阶段流程
4. 当前阶段 Agent 建议（为什么、重点、风险、下一步）
5. 生成话术/物料或执行动作
6. 记录客户反馈
7. Agent 自动复盘，更新评分、阶段和 Next Best Action

所有线上/线下行为统一进入 Customer Timeline，不让用户在多个模块间跳转拼流程。

## 与未来项目管理界面的统一
统一采用“工作房间 / Object Room”骨架：
- 左侧：对象/项目/客户列表
- 中间上方：对象状态、阶段/里程碑、当前目标
- 中间主体：当前工作面 + 实时动态/时间线
- 右侧：人 + Agent + 当前关键任务/建议
- 底部：自然语言控制面，Agent 可把指令转成结构化变更
- 变更执行前按风险显示预览：字段变化、任务变化、产物变化、负责人/截止时间变化

市场版只替换领域逻辑，不替换交互骨架。
项目管理映射示例：
- 客户阶段 → 项目里程碑
- 商机评分 → 项目健康度
- 客户互动 → 开发/决策事件
- PoC/方案产物 → 代码、文档、PR、发布物

## 客户评分机制
评分不是“这家公司好不好”，而是回答“当前是否值得继续投入销售资源”。

建议保留两个面向用户的数字：
A. Opportunity Score（机会分，0-100）
- Product Fit 20%
- Need 20%
- Intent 15%
- Timing 15%
- Company Fit 10%
- Relationship 8%
- Contactability 7%
- Trade / external signals 5%
- Opportunity Score = Σ(维度分 × 权重)

B. Evidence Confidence（证据置信度，0-100）
用于回答“我们对上述判断有多确信”，依据：
- 一手客户互动证据
- 官方/可信来源质量
- 独立来源数量
- 新鲜度
- 证据一致性
- 可追溯性

原则：
- 置信度不直接混进机会分，避免“证据少 = 商业价值低”的错误。
- 高机会 + 低置信：下一步应补证据。
- 高机会 + 高置信：进入重点投入。
- 低机会 + 高置信：可降优先级。
- 每次分数变化必须能展开看到“新证据 → Agent 判断 → 哪个维度变化 → 更新时间”，禁止黑箱跳分。
- 若需要列表排序，可使用：推荐排序分 = Opportunity × (0.7 + 0.3 × Confidence/100)，但界面仍优先显示机会分与置信度两个原始量。

关键设计收敛：
- 不再要求用户在多个模块间拼流程。
- 一个客户进入后主要留在同一“客户作战房间”。
- 当前阶段只突出一个 Next Best Action。
- Agent 不是额外页面，而是侧栏 + 动态 + 控制面。
- 生成话术时必须解释“为什么这样写”：公司性质、阶段目标、证据、避免项。
- 会后记录事实，Agent 提取证据并建议阶段/评分/任务变化。
- 阶段完成后显示做得好、需改进、评分变化、下一阶段工作面。
- 通用房间证明这套结构可以无缝迁移到项目管理等后续模块。

## 视觉约束
- 继承当前 AragonTeam：白 / 暖米底、橙色主强调、克制圆角、细边框、弱阴影。
- 避免把每个能力做成独立大卡片或独立页面。
- 一屏只突出一个当前目标 + 一到两个辅助动作。
- 所有建议必须能落到 Action / Owner / Deadline / Approval / Result。
