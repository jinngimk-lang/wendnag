# AegistonTeam 客户版 Deck 视觉系统 V1

## 一、设计目标

客户版应呈现“可信的企业软件产品 + 清晰的工程过程 + 可审查的交付证据”，而不是培训教材或 AI 概念宣传册。

核心视觉中心：
1. 真实产品界面；
2. 人与多智能体协作关系；
3. 需求、任务、代码、测试、评审和版本的连续过程；
4. 企业治理与数据边界；
5. 可复核的试点结果。

吉祥物用于轻量品牌识别、引导和局部强调，不作为董事会/CTO 提案的主要画面。

## 二、三个视觉方向尝试

### A. Enterprise Command Center（主 Deck/管理层）

- 深海军蓝、暖白、品牌橙。
- 以“任务流、角色关系、执行轨迹、结果证据”为主。
- 封面可用抽象的任务网络/流程图形，不使用廉价科幻粒子。
- 关键数字只在有证据时放大。
- 适合董事长、总经理、CTO 的主 Deck。

### B. Product Evidence（产品/研发演示）

- 白底或极浅灰背景，大面积真实 UI 截图。
- 以界面局部放大、标注、代码 diff、测试报告和任务时间线组织信息。
- 一个页面只解释一个产品动作。
- 适合研发负责人和产品负责人。

### C. Business Outcome（业务价值/试点）

- 暖白底、少量橙色强调、简洁流程和指标图。
- 用同类任务前后对照、基线与试点、成本构成图展示价值。
- 不用未经验证的百分比或“提升 X 倍”装饰页面。
- 适合业务负责人、财务和采购。

## 三、临时色彩建议

产品 HTML 原型 CSS 中观察到：
- 深蓝：#0D1C64
- 橙红：#FF4A1D
- 背景：#FCFDFF
- 辅助蓝：#6980B7

2026-10-28 的产品设计锚点另记录过：
- 强调橙：#D75F35
- 浅灰：#F3F5F9
- 深色文字：#292622
- 卡片：#FFFFFF

两套值并不完全一致，且原项目文档明确说明这些属于原型观察，不是最终品牌规范。当前仅作为视觉探索变量；正式定稿前应以品牌负责人确认的 Logo/官网设计系统为准。

## 四、版式规则

- 页面尺寸：保持 16:9。
- 主标题建议 28–36 pt；正文 18–22 pt；注释 12–14 pt。
- 每页一个主结论，最多 3 个支持点。
- 表格只用于比较、责任分工、验收标准；能用流程图或图表说明的，不用长表格。
- 重要流程横向展示，明确人类确认点、Agent 执行点和输出产物。
- 真实 UI 截图需标明当前版本/原型状态；不得 AI 重绘成不存在的功能。
- 产品截图不遮挡真实文字；若截图质量不足，先重做产品演示环境。
- 避免通用卡通会议插画、通用办公人物图库、随机发光粒子和无意义装饰。
- 保留足够留白，但不能用大片空白替代产品证据。

## 五、建议建立的页面模板

1. **Hero 封面**：一句品类主张 + 一张产品/流程视觉。
2. **问题对照**：传统流程与人机协同流程对照。
3. **角色架构**：人类负责人、数字 FDE、专业 Agent、项目上下文。
4. **端到端流程**：需求到交付的连续步骤。
5. **产品截图讲解**：截图 + 3 个标注 + 输出结果。
6. **代码/测试证据**：代码 diff、测试通过/失败、人工评审。
7. **变更闭环**：需求变化前后、影响、修改、回归验证。
8. **安全/部署架构**：数据流、权限、模型调用和边界。
9. **ROI 对照**：同类任务基线与试点数据。
10. **试点路线图**：范围、周期、双方责任、验收门槛。
11. **商业合作**：许可、实施、集成、算力、运维分项。
12. **下一步 CTA**：具体会议、材料、负责人和日期。

## 六、视觉验收

- 远距离投屏能否读清标题和结论？
- 观众能否在 5 秒内知道这一页要说明什么？
- 每张图是否来自真实产品/真实数据，或明确标记为概念示意？
- 是否有一页同时塞入过多文字、表格和图形？
- 是否把“可用能力”和“规划能力”混在一张图里？
- 品牌色、字体、圆角、图标、线宽和页脚是否统一？
