# AegistonTeam 企业销售提案工作流

> 建立日期：2026-11-06  
> 当前阶段：V1 审计与重构方案  
> 工作分支：sales/aegistonteam-enterprise-deck-audit-20261106

## 目标

把《大型企业销售方案V2_完善版》从一份兼具获客、销售管理、沟通培训、提案与试点的 91 页内部执行材料，拆分并重构为：

1. **客户版主 Deck**：让企业决策者理解 AegistonTeam 的品类、价值、工作方式、证据、部署边界、试点和合作路径。
2. **内部大客户销售作战手册**：保留账户准备、渠道、沟通话术、岗位协同、复盘和 90 天执行机制。
3. **按岗位和行业定制的模块**：管理层、研发负责人、IT/安全、采购，以及少量优先行业场景。
4. **产品演示与试点证据包**：真实任务输入、智能体协作、人工介入、代码/测试产物、变更记录、验收和成本。

## 当前工作定位

用户当前定义：AegistonTeam 是一款线上多智能体与人协作的软件开发平台，由数字 FDE 从需求拆解开始，组织人和多智能体协同推进，形成可交付的软件开发闭环。

**工作定位草案（对外使用前需与当前可运行版本逐项核验）：**

> AegistonTeam 是面向企业研发与项目交付的多智能体人机协同平台，让业务需求、任务拆解、智能体协作、人工评审、研发验证与持续迭代在同一项目上下文中衔接。

品类描述优先采用：**企业级人机协同软件开发平台**。  
数字 FDE 是产品机制，不应只作为没有解释的术语出现。

## 事实与承诺规则

所有信息分为四种状态：

- **已验证**：当前版本可重复运行，并有可复查结果。
- **已实现、待企业环境验证**：功能已完成，但尚缺企业部署/验收证据。
- **设计/原型**：已有界面、交互或架构设计，不等于生产能力。
- **规划**：尚未实现，不进入当前销售承诺。

严格遵守：

- 当前用户定义用于产品定位；不能自动推导为每项功能已经生产可用。
- 2026-11-04 的内部增长方案记录了当时 HTML 原型为本地交互演示，部分内容未连接真实模型执行或实时共享。此为历史证据，必须与最新版本重新核验。
- 不把 AragonTeam 历史名称继续带入客户材料；当前统一使用 AegistonTeam，但旧截图/图表需逐项检查。
- 不把合约智审 LegalLens 的效率数字、客户案例或验收结果转移到 AegistonTeam。
- 公司级客户名单不自动等于 AegistonTeam 客户；须确认采购产品、范围和宣传授权。
- 不把“应用本地运行”直接等同于“模型推理、插件、遥测、更新均不外联”。
- 不承诺未验证的连接器、权限隔离、审计、私有化、SLA、代码所有权或 CI/CD 能力。
- 规划、推断、公开资料、客户确认事实必须分开标注。

## 工作方法

1. 先读本目录 README、STATUS、SOURCE_REGISTER 和最近一次 checkpoint。
2. 先保护原始 91 页销售手册，不覆盖、不静默改写。
3. 每次只在独立分支做可逆、可审查的增量工作。
4. 内容先证据审查，再叙事重构，再视觉制作。
5. 先做 3 种叙事/视觉方向的样张，再选定主方向。
6. 每个关键卖点都要绑定可演示产物或明确标记为待验证。
7. 输出客户版和内部版时，分别检查受众、长度、承诺边界和 CTA。
8. 重要结论、被否决方向、待确认问题和下一步写回 STATUS。
