# AegistonTeam 产品卖点与证据控制 V1

## 原则

销售材料可以清楚表达产品定位，但每项具体能力、效率、安全、集成、部署、服务和客户成果必须有对应证据。没有证据时写“待验证”，而不是包装成既成事实。

## 能力表达与证据要求

| 销售表达 | 客户可能如何理解 | 最低证据 | 没有证据时的说法 |
|---|---|---|---|
| 线上多智能体与人协作的软件开发平台 | 有真实在线产品和协作功能 | 当前发布环境、真实用户和任务运行 | 说明当前演示环境和可用范围 |
| 数字 FDE 进行需求拆解 | 能理解需求并形成可执行任务 | 真实输入、追问、结构化需求、人工确认 | 展示概念/设计流程并标注状态 |
| 多 Agent 协作 | 多个 Agent 真正分工、交接和执行 | 运行日志、角色配置、任务状态和异常处理 | 不把静态角色图说成实际运行 |
| 人工协作与审批 | 人能在关键点介入和控制 | 人工确认界面、权限和审查记录 | 说明当前人工介入方式 |
| 代码生成/修改 | 可产生可合并的代码 | 代码 diff、仓库状态、Review | 只展示代码示例，不声称已集成 |
| 自动测试/验证 | 实际运行了测试 | 测试命令、结果、失败样例 | 说明测试需客户环境/人工执行 |
| 需求变更后继续开发 | 项目上下文持续保留 | 变更记录、任务影响、代码和回归证据 | 作为待验证演示场景 |
| Git/Issue/CI 等集成 | 已经端到端连接 | 当前版本真实连接测试 | 列出已支持、需适配、未支持 |
| 权限/审计/日志 | 可满足企业治理 | 权限矩阵、越权测试、日志样例 | 不做“全程可追溯”承诺 |
| 私有化/内网部署 | 当前产品可部署并运行 | 部署手册、网络图、模型调用和运维责任 | 列为方案评估，不作为现货承诺 |
| 数据不外传/不用于训练 | 所有相关数据链路均受控 | 模型/子处理方、数据流、留存/删除条款 | 明确具体模型和数据流待核验 |
| 提效/降本数字 | 有真实、可复用结果 | 多次同类任务基线、成本和验收 | 不引用统一倍数或百分比 |
| 客户案例 | 客户真实采购/使用 AegistonTeam | 合同/项目范围、实际使用和宣传授权 | 公司案例与产品案例分开 |
| SLA/支持时限 | 可写入合同并持续履约 | 服务团队、值守安排、批准 SLA | 仅提供当前可承诺支持方式 |
| 代码/IP 归属 | 有明确合同权利 | 经法务确认的合同条款 | 不作口头法律承诺 |

## 销售可用的证据状态标签

- 已验证：当前版本可重复运行，且有记录。
- 已实现、待客户环境验证：功能已完成，但还未在客户条件下验证。
- 原型/设计：只证明设计意图，不证明生产能力。
- 规划：尚未完成，不作为当前承诺。
- 待确认：资料不足，需产品/研发/法务核实。

## 绝对禁止

- 把 LegalLens 或其他产品的客户案例、效率数字移植给 AegistonTeam；
- 把公司客户名单自动写成 AegistonTeam 客户名单；
- 把静态界面、模拟数据、剪辑录屏说成实时生产运行；
- 把产品导航入口说成 Git/CI/SSO 等集成已完成；
- 把“应用本地运行”说成模型、插件、遥测、更新和备份都不外联；
- 没有权限测试和日志证据就承诺企业级治理已完成；
- 没有正式批准就承诺 SLA、私有化、报价、代码/IP 归属或数据删除条款。

## 每次客户演示前的核验清单

- [ ] 当前产品版本、环境和账号已确认；
- [ ] 每个展示功能均能在当前版本重现；
- [ ] 真实执行与录屏回放已明确区分；
- [ ] Agent 角色、工具和权限已核实；
- [ ] 代码、测试、Review 产物可复查；
- [ ] 失败和人工介入方式已说明；
- [ ] 模型、数据和外部服务调用边界已核实；
- [ ] 未实现或需适配的内容已列明；
- [ ] 演示数据已脱敏；
- [ ] 所有数字、案例和客户名称有来源与使用授权。
