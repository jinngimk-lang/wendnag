# Capital Theater — 资金可视化擂台 V0.2

本目录是 AI Arena 的**并行、可审查视觉方向**，而非直接在第一版控制室里不断加按钮。用户的关键需求是「盈利时美元向 Agent 聚集、亏损时钞票倒流、观众一眼看懂钱的变化」。本版优先验证 **资金运动作为主画面** 的新范式。

## 立即运行

打开 `index.html`。它是完整、可编辑、无外部依赖的 HTML/CSS/JS 单文件，也可以用任意静态 HTTP 服务器打开；不需要 Node 安装、API Key、Figma 或第三方 CDN。

## 已实现

- 四个 Agent 从同样的 $100,000 模拟本金出发，六轮演示数据完全公开于前端代码。
- 中央模拟净盈亏金库、四角选手资金栏和物理方向一致的绿色/红色钞票流动画；盈利流向 Agent，亏损流离 Agent。
- 动画只在 `rounds` 净回报跨轮变化时触发，不反向修改收益模型。
- 真实按复利计算的余额、累计损益、最大回撤、风险调整分数、模拟基准和历史净值曲线。
- 启动、暂停、恢复、下一轮、直达结算、重置、拖动进度条复盘，以及明确的规则弹窗。
- 可关闭的 Web Audio 点缀（默认关闭），系统减少动态效果时不生成飞行纸币。
- 输入任意公司名称**仅更新比赛标题，不改变固定示例曲线**，避免伪造真实公司预测。
- 桌面、平板和手机布局，直接写进一个 HTML 文件，后续可以原样导入任意网站项目。

## 视觉设计的转向

第一版是 **Broadcast Control Room / 金融看板**：数字、曲线和榜单为主，华丽但不直接感受到钱。
本版是 **Capital Theater / 资金成为演员**：全屏金库、四周选手、可逆资金流、结算仪式。它借鉴舞台表演和博彩游戏的即时反馈，但不包含下注、赔率、付费投注、保底收益或伪造的盈利证据。

为什么暂时不用外部 3D 引擎：这轮已用 CSS 透视、阴影、纹理、SVG 装饰和 Web Audio 验证核心体验。只有在用户测试确认资金动效改善理解度，而不是只增加兴奋度后，才升级到 PixiJS / GPU 粒子、Rive 状态机或 Three.js 的高性能版本。高仿真镜头与静态渲染适合在确定镜头后再加入；不能将画面特效当成市场仿真数据。

## 数据模型

- 本金：`100000` 美元/Agent，固定四人。
- 每轮：`balance[t+1] = balance[t] × (1 + netReturn[t])`；示例回报已含假设费用。
- 累计收益率：`100 × (balance/startingCapital - 1)`。
- 回撤：相对该策略到目前为止历史峰值的最大跌幅（百分比）。
- 比赛分数：`cumulativeReturnPct - 0.45 × maxDrawdownPct`。这是演示评分公式，不是科学验证的最优风险度量。
- 同一 round 输入的状态可以确定性重算；拖动回放不会应用加倍收益。
- 模拟基准是自造的 `S&P-like fixture`，**不是**任何实际指数的历史回报。

## 测试

```bash
python -m venv .venv
.venv/bin/python -m pip install playwright
.venv/bin/python -m playwright install chromium
.venv/bin/python tests/test_ui.py
```

测试脚本优先使用 `/usr/bin/chromium`（已存在时），用 `page.set_content` 加载 HTML，因此不依赖访问外网或本地 HTTP 导航。

## 可信度边界

**这不是投资建议、真实模拟撮合或可预期收益。** 没有行情、财报、真实 Agent 推理、券商连接、成交或新闻数据。用户输入任何公司名称不会产生该公司的真实回测。投产前需要完整市场数据许可、时点数据、账户/风险隔离、撮合成本、事件账本和回测评估。

## 何时弃用此方向

若测试显示受访者误把演示数据理解为未来预测、无法识别风险、资金动画只增加兴奋而不增加理解，或移动端掉帧明显，则减少或移除赌场语法，保留可审计资金流。不要因为已经实现就继续堆砌特效。
