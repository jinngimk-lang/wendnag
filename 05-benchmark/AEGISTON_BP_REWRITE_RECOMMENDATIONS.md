# 智瞳安宇 BP 对标分析与详细改版建议

> 基于仓库当前 11 个正文模块、主要图表生成逻辑，以及 10 家 AI / 互联网 / 具身智能公司融资叙事对标。

---

## 一、结论先行：当前 BP 最大的问题不是“内容不够”，而是“最强内容没有被排在最前面”

现有 BP 有三个明显优点：第一，企业 Agent 上生产所需的身份、权限、流程、审计逻辑已经形成相对完整的方法论；第二，通信与交通客户的量化结果很强；第三，研发团队和私有化交付能力具备真实壁垒。

但投资材料的表达顺序把这些优势削弱了：

1. 一开场同时讲 AragonTeam、AegisClaw、LegalLens 三层产品，投资人难以迅速判断“公司到底最核心卖什么”。
2. 第二、三章花较多篇幅解释公司背景、市场 CAGR、政策和行业预测，真正能建立信任的客户数据直到第八章才出现。
3. 技术壁垒描述专业，但“为什么这些技术让客户更愿意买、让竞争者更难追、让毛利更高”连接不足。
4. 商业模式有四条收入线，加上软件、云、私有化、一体机，容易被理解为业务边界过宽、项目制较重。
5. 竞争分析主要是抽象类别，没有把投资人脑中的 Microsoft Copilot、Cursor/Claude Code、Jira/GitLab、法律 AI、传统系统集成商等替代方案一次讲清。
6. 视觉统一但偏“行业研究报告/政府项目汇报”，说明性框图多，真实产品、客户证据、数字冲击力不够。

因此，本轮改版不建议继续“补内容”，而应该做一次结构性减法。

# 二、P0：必须立即修改的 10 个点

## P0-1｜重写公司一句话定位

### 当前

> 「AI+」企业智能化赋能与安全保障专家

问题：这句话可以被大量 AI 软件公司、系统集成商、网络安全公司使用，没有把公司的核心类别说出来。

### 推荐方向 A（最适合融资）

> **让企业智能体真正进入生产：身份、权限、流程与审计一体化的企业 Agent 运行平台。**

副标题：

> 从合同审查与强监管流程切入，已在通信、交通等行业完成私有化交付和跨区域复制。

### 推荐方向 B（更偏产品类别）

> **企业数字员工的治理与执行底座。**

副标题：

> 让 Agent 拥有正式身份、明确权限、流程状态和全链路审计，在企业内网稳定完成工作。

### 推荐方向 C（更偏国内政企采购语境）

> **面向政企核心流程的可信智能体平台。**

副标题：

> 支持私有化、信创适配、权限治理与审计留痕，让 AI 从个人工具升级为组织生产力。

建议：主 deck 用 A，政企销售材料可用 C。

## P0-2｜三层产品不要在首页平铺，改成“一个底座 + 两类应用证明”

当前的组织级、通用级、行业级三层逻辑在技术上合理，但在融资叙事里会让投资人产生三个疑问：

- 三款产品谁是主产品？
- 团队是否同时做太多？
- 三款产品之间收入和客户是否真的共享？

### 建议重构

**公司主产品：Aegiston Enterprise Agent Runtime / 企业智能体生产运行层**

其下分三种能力：

1. **治理与协作层**：AragonTeam
2. **安全执行层**：AegisClaw
3. **行业应用层**：LegalLens

但主 deck 不再把三者做成完全平级的“三家公司式产品矩阵”。

更好的表达是：

> **底座负责让 Agent 能安全进入企业；LegalLens 证明它在强监管流程里已经创造结果；AragonTeam 负责把同样能力扩展到研发和组织协作。**

AegisClaw 如果目前独立商业收入较弱，应作为底层能力/云端执行环境，而不是和另两款产品抢叙事中心。

## P0-3｜把 Traction 从第 8 章移动到第 4 页

当前 BP 最有投资价值的数据包括：

- 单份合同审核 3.5 小时 → 10 分钟
- 法务人均产能 35 份/月 → 105+ 份/月
- 累计审核 500+ 份
- 识别关键风险 1280 项
- 人工确认有效风险率 86%
- 数千份真实商业合同脱敏入库
- 标注一致性 >95%
- 关键条款识别准确率 >98%
- 交通项目审核周期 1 天 → 10 分钟
- 跨合同比对人工时间下降 64%
- 陕西模式已复制到福建、湖北、湖南等分公司

这些数字比“2030 年市场规模 460.4 亿美元”更能让投资人相信公司。

### 推荐第 4 页标题

> **不是试验：我们已经把企业合同审查从小时级变成分钟级，并完成跨区域复制。**

页面只保留 4–6 个大数字 + 1 张复制地图/客户流程图。

## P0-4｜把市场章节从“宏观预测”改成“为什么现在企业必须买”

当前市场章节包含多条机构预测、政策目标、Agent 数量等信息，容易出现“研究报告感”。

### 建议保留最多 3 个外部信号

1. 企业 Agent 正从 Copilot 走向自主执行；
2. 中国政企对数据不出域、私有化、审计留痕要求构成结构性门槛；
3. 大量企业 AI 试点停留在个人工具层，生产化缺口仍然存在。

### 必须新增：Bottom-up 市场测算

不要只给全球 TAM。建议按真实客户类型测算：

- 通信省公司/集团数量 × 典型私有化客单价
- 省级交控/交通基建集团数量 × 客单价
- 重点央国企/大型集团法务部门数量 × 客单价
- 律所/金融机构目标客户数量 × 客单价

至少形成：

**TAM（全企业 Agent 平台） / SAM（中国强监管行业） / SOM（未来 3 年渠道可触达客户）**

SOM 要与销售团队和中通服渠道覆盖能力对应。

## P0-5｜竞争页必须出现“具名替代方案”

当前把竞品分为“个人办公助手、编码智能体、研发平台”等类别，逻辑没有错，但投资人会怀疑是不是在回避真正的竞争。

### 推荐竞争框架

第一张 2×2：

横轴：**个人工具 → 组织生产系统**

纵轴：**公网 SaaS → 私有化/强治理**

在图中标出代表性替代方案，例如：

- Microsoft 365 Copilot / ChatGPT Enterprise：企业助手
- Cursor / Claude Code / GitHub Copilot：研发执行
- Jira / GitLab / 禅道：研发流程
- 国内外法律 AI / 合同审查产品：垂直应用
- 传统系统集成商：私有化能力强，但 Agent 产品化弱
- 智瞳安宇：Agent + 组织流程 + 私有化 + 审计治理

第二张只做核心差异：

| 能力 | 通用助手 | 编码 Agent | 流程平台 | 垂直法律 AI | 智瞳安宇 |
| --- | --- | --- | --- | --- | --- |
| Agent 正式身份 | 弱 | 弱 | 无 Agent | 弱 | 强 |
| 企业权限治理 | 中 | 中 | 人员权限 | 中 | 强 |
| 流程状态/回边 | 弱 | 弱 | 强 | 中 | 强 |
| 全链路审计 | 中 | 中 | 强 | 中 | 强 |
| 私有化/断网 | 部分 | 部分 | 部分 | 部分 | 强 |
| 领域规则持续沉淀 | 弱 | 弱 | 弱 | 强 | 强 |

具体公司名称需要在最终发布前逐项核验功能，避免过度断言。

## P0-6｜把技术页从“技术清单”改成“4 个难以复制的商业壁垒”

当前技术章节很强，但写法偏论文摘要。建议改成：

### 壁垒 1：Agent 治理运行时

**客户价值：**敢授权、能审计、能追责。

**技术证据：**身份注册表、权限策略、执行链审计、流程状态。

**商业壁垒：**与客户现有身份、流程、内网系统深度融合，替换成本高。

### 壁垒 2：可回边、可重入的长流程执行内核

**客户价值：**真实审批/评审流程不是一次性直线任务。

**技术证据：**运行图、状态持久化、等待契约、异常恢复。

**商业壁垒：**决定系统能否长期稳定跑生产任务。

### 壁垒 3：行业规则与知识资产

**客户价值：**不是“通用模型会不会读合同”，而是能否理解客户自己的制度与历史口径。

**证据：**12 个月共建、数千份合同、73 项风险规则、跨省复制。

**商业壁垒：**使用越久，客户切换成本越高。

### 壁垒 4：私有化与安全交付能力

**客户价值：**数据不出域、断网运行、信创兼容。

**商业壁垒：**进入国企、央企、金融等客户的结构性准入条件。

AragonMesh / KV-Cache 直连建议保留，但放成“性能与成本优势”子证据，除非已经有真实 benchmark。

---

## P0-7｜商业模式必须回答“是不是项目公司”

现有四条收入线完整，但投资人容易看到：私有化 + 一体机 + 实施 + 规则库共建，然后判断“服务收入重、规模化难”。

### 必须新增的 6 个指标

如果已有数据，应直接放；如果没有，先在内部建立统计：

1. 软件授权/订阅收入占总收入比例
2. 实施收入占比
3. 年度运维/续费率
4. 单客户扩容/追加采购率
5. 标准交付周期（首单 vs 同行业第 N 单）
6. 单项目实施人天 / 毛利率变化

### 页面叙事

> **首单共建规则 → 形成行业模板 → 第二家开始复用 → 实施周期下降 → 软件毛利提高 → 渠道复制。**

这条“复制曲线”比四条收入线本身更重要。

## P0-8｜融资页改成“18 个月能力跃迁”

当前：1000 万元、10%、投后 1 亿元；40/20/20/12/8 分配。

建议保留金额与比例，但主标题改为：

> **本轮 1000 万：完成从标杆项目交付到标准化行业复制的跨越。**

### 建议 18 个月里程碑模板

> 以下目标数值必须由管理层确认后再写入正式 BP，不能凭空填。

- **产品**：三层产品收敛成 1 套统一商业版本；私有化部署标准包交付周期降至 X 天
- **客户**：新增 X 家付费客户，其中 X 家来自中通服/渠道复制
- **收入**：年度合同额/确认收入达到 X 万；经常性软件/运维收入占比达到 X%
- **行业**：至少新增 1–2 个可复用行业规则包
- **交付效率**：同行业第 N 单实施人天比首单下降 X%
- **硬件**：一体机仅在有订单验证情况下形成标准 SKU 与毛利目标

资金比例放在页底，不要作为页面主角。

## P0-9｜删除或弱化容易被投资人追问的过度表述

### 需要重新核验或调整措辞

1. “政策把是否用上智能体变成考核项”——政策目标不等于每个政企客户的直接考核项，建议改为“形成明确政策推动与采购环境”。
2. “95% 企业 GenAI 试点无可衡量回报”——可作为背景信号，但来源与定义容易被追问，不建议成为核心论据。
3. “全球 22 亿 Agent”——过于宏观，且与公司收入模型没有直接关系，建议删除。
4. “大量顶会论文/100+ 专利/30+ 核心技术”——当前不同章节口径不同，必须统一“申请、授权、公司拥有、团队历史成果”的区别。
5. “法律与金融已完成私有化部署方案的产品销售”与“已完成私有化部署”表述要统一。
6. “估值主要基于三方面支撑”——估值页不要尝试自证一个精确估值公式，更多强调融资后里程碑和可比进展。

## P0-10｜视觉从“说明图”升级成“证据图”

现有图表源文件视觉风格统一：海军蓝/浅蓝、圆角卡片、结构清晰；这是优点。但目前主图多数是：

- 三层产品架构
- 市场规模柱图
- 四级能力阶梯
- 三种交付形态
- 四层技术架构
- 收入/复制路径
- 资金用途
- 三年里程碑

这些图“解释公司”很多，“证明公司”较少。

### 主 deck 建议保留的说明图最多 3 张

1. Before / After：个人 AI → 企业 Agent
2. 一个统一底座 + 应用层
3. GTM/行业复制飞轮

### 必须新增 5 类证据图

1. 客户量化结果大数字页
2. 跨省/跨行业复制地图
3. 产品真实截图（权限、流程、审计）
4. 客户案例前后流程
5. 收入/合同/客户增长时间线

市场柱图、资金用途图、四层技术架构可以放 appendix。

# 三、推荐重做成 12 页主融资 Deck

## 第 1 页｜封面：一句话定义品类

### 标题

**让企业智能体真正进入生产**

### 副标题

身份、权限、流程与审计一体化的企业 Agent 运行平台

### 证明行

通信/交通已量化验证｜强监管行业私有化部署｜跨省复制进行中

视觉：1 张高质量产品工作流画面，不放三层产品框图。

---

## 第 2 页｜问题：模型会做事，但企业不敢让它上生产

用 Before / After：

| 个人 AI 时代 | 企业生产要求 |
| --- | --- |
| 个人账号 | 正式企业身份 |
| 谁都能复制粘贴 | 最小权限 |
| 聊天结束即结束 | 有状态流程 |
| 无法追责 | 全链路审计 |
| 公网调用 | 私有化/数据不出域 |

结论：

> **模型能力不是企业 Agent 落地的最后一公里；治理与执行系统才是。**

---

## 第 3 页｜解决方案：一套运行底座，让 Agent 成为正式数字员工

中间：统一企业 Agent Runtime

四个能力：身份与权限 / 知识与上下文 / 流程与状态 / 审计与留痕

下方展示两个应用入口：

- LegalLens：合同与强监管业务流程
- AragonTeam：研发与项目交付流程

AegisClaw 作为安全执行/云沙箱能力内嵌，不抢主视觉。

---

## 第 4 页｜Traction：先看结果

标题：

**我们已经让 AI 在真实企业流程中产生可量化结果。**

大数字：

- 3.5h → 10min
- 35 → 105+ contracts/person/month
- 500+ contracts reviewed
- 1280 key risks identified
- 4 provinces replicated

底部：通信 / 交通 / 法律 / 金融成熟度标签。

---

## 第 5 页｜案例：为什么客户不是试完就走

以中通服为主：

12 个月共建 → 数千份合同 → 规则库 → 陕西验证 → 福建/湖北/湖南复制

强调：

> **首单交付沉淀的规则资产，可以直接降低同行业下一单的实施成本。**

这页实际上是在证明 moat + GTM + unit economics。

---

## 第 6 页｜Why Now：三个拐点同时发生

只保留 3 个：

1. Agent 从回答走向执行；
2. 企业核心流程要求身份、权限与审计；
3. 中国强监管行业要求私有化与数据不出域。

不要放 6–10 个机构预测。

## 第 7 页｜市场：从真实采购单位算 SAM/SOM

用 bottom-up：客户数量 × ACV × 可触达率。

例如结构：

| 客群 | 可服务组织数 | 典型 ACV | SAM |
| --- | ---: | ---: | ---: |
| 通信集团/省公司 | 待核验 | 待核验 | 待核验 |
| 交通/交控集团 | 待核验 | 待核验 | 待核验 |
| 金融/信托 | 待核验 | 待核验 | 待核验 |
| 大型企业法务 | 待核验 | 待核验 | 待核验 |

宏观 Agentic AI 市场规模作为旁注。

## 第 8 页｜竞争：为什么现有工具不能替代

一张 2×2 + 一个 5 行对比表。

核心论点：

> 通用助手缺少组织流程；流程系统没有 Agent；垂直 AI 缺统一治理底座；传统私有化方案缺产品化的智能体执行层。

---

## 第 9 页｜技术与数据壁垒：四层壁垒都能被客户验证

1. 治理运行时
2. 长流程执行内核
3. 行业规则与知识资产
4. 私有化与安全交付

每层用“客户价值 + 技术证据 + 已验证事实”三列。

## 第 10 页｜商业模式与复制飞轮

核心图：

首单共建 → 规则模板化 → 渠道复制 → 实施周期下降 → 软件收入占比提升 → 更多行业数据/规则

右侧列 5 个真实经营指标；如果当前没有，明确列为融资前必须补的数据。

---

## 第 11 页｜团队：为什么是这支团队

不要只列荣誉。

建议按能力拼图：

- **Founder / 科研与产业**：李金库——科研、百人研发管理、成果转化
- **CTO / 工程化**：焦瑞——华为 AI 与全栈系统落地
- **核心算法**：多智能体、模型、合同一致性
- **交付能力**：谁负责中通服/交控落地
- **商业化能力**：谁负责渠道、销售、客户成功

若销售/GTM 目前是团队短板，公开写“本轮融资重点补齐的核心岗位”，反而比回避更可信。

## 第 12 页｜融资：1000 万买到什么

标题：

**从标杆项目交付，跨到标准产品复制。**

左侧：融资 1000 万 / 10% / 投后 1 亿

右侧：18 个月 3–5 个里程碑。

# 六、现有图案/版式的具体修改意见

## 图 1 三层产品底座

**问题：**三个产品权重完全相同，强化了“公司做三件事”的印象。

**改法：**中心放统一 Agent Runtime；LegalLens 和 AragonTeam 作为两个实例；AegisClaw 作为安全执行层嵌入底座。

## 图 2 Agentic AI 市场规模柱图

**问题：**视觉清楚，但属于低差异化信息。

**改法：**移 appendix。主 deck 市场页做 bottom-up。

## 图 3 四级能力阶梯

**问题：**逻辑完整，但抽象教育成本高。

**改法：**替换成 Before/After 企业流程。

## 图 10 三种交付形态

**问题：**三种交付形态说明太早会把公司讲成集成/交付公司。

**改法：**放商业模式或 appendix；主 deck 只强调“支持私有化/断网”。

## 图 11 LegalLens 四层架构

**问题：**是典型技术架构图，对投资人说服力有限。

**改法：**替换成真实合同流程：上传→AI 审核→风险证据→人工复核→规则沉淀。

**问题：**这是现有最值得保留和强化的一张逻辑图。

## 图 16 三年里程碑

**改法：**每个里程碑只允许出现可量化验收项：客户数、收入、部署时间、行业模板、软件收入占比等。

# 九、最终判断

智瞳安宇现在不是缺“故事素材”，而是素材过多、主线不够单一。

最值得投资人记住的不是“三层产品、四类要件、九项功能、十一项功能、四条收入线”，而应该是：

> **企业 Agent 真正上生产，需要身份、权限、流程和审计。智瞳安宇已经在最难的强监管客户里把这件事跑通，并正在把项目经验变成可复制的产品与行业资产。**

只要把整份 BP 围绕这句话重新排序，现有客户数据、技术积累、私有化能力和高校背景都会成为同一条证据链，而不是彼此竞争注意力的四组信息。
