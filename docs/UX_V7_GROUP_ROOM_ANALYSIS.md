## 二、设计判断

**产品定义：** “群聊”不只是即时通讯，而是项目执行上下文。建议同一个群聊入口同时容纳普通群与**关联项目的房间**，不要另加一级或二级项目菜单。

**蓝队（可用性）的保留项：**
1. 明确的项目房间标题、描述、成员与 Agent、关联资源入口。
2. 聊天与动态形成连续协作证据，可以按“全部/讨论/Agent 动态/系统”过滤。
3. 右侧“当前任务”显示状态、负责人、截止时间、点击打开任务详情，并可一键转入现有需求/BUG 看板。
4. 消息“回复/引用/转需求或任务”按需出现，创建草稿有确认步骤。
5. 人类与 Agent 具备明显不同的身份标识；Agent 的运行状态可展开查看步骤/产物/待审批。

**红队（复杂性与风险）的反对项：**
1. **不复制**整张高密度布局。永久双侧栏会让 v6 的一级 rail + 二级菜单 + 群聊列表 + 右侧栏构成四重导航，在笔记本/手机上挤压主内容。
2. **不混淆**人的讨论消息、Agent 过程记录与系统更新。系统日志可折叠为摘要，默认强调可行动消息；保留快速过滤。
3. **不新建**重复的项目任务数据库/任务详情页。群聊里的任务卡只读复用现有项目需求/BUG 对象；“新任务”走现有任务创建演示弹窗。
4. **不造假**在线人数、真实工作状态、Agent 进度或 Token。所有演示数据注明“本地演示”，状态演示须有对应详情，不模拟生产连接。
5. **不为每种能力增设侧边导航**。项目菜单保持七项：项目管理 / 需求看板 / BUG看板 / 文档 / 代码仓 / 建议 / 版本；一级四项保持智能体 / 项目 / 团队 / 个人，设置在底部。

## 三、拟采用的页面层级

```
全局一级导航 [智能体] + 二级 [群聊]（不新增入口）
┌──────────────────────────────────────────────────────────────────┐
│ 项目房间 · Legallens 开发优化 [进行中] [成员 6] [更多]           │
│ 描述一行；关联项目 [需求看板] [项目文档] [代码仓]                │
├───────────────────────────────────────────┬──────────────────────┤
│ [当前房间 ▼] [全部 | 讨论 | Agent动态 | 系统] │ 参与者 / 任务        │
│                                           │ 人类 3 / Agent 3     │
│ 时间线：人类消息、Agent 运行卡、变更摘要   │ 当前任务 4（可点击） │
│ [折叠 5 条系统更新]                        │                    │
│                                           │                    │
│ 输入框：@ / 引用 / 附件（演示）   [发送]    │                    │
└───────────────────────────────────────────┴──────────────────────┘
```

- 1280px 以上：保留右侧紧凑信息栏（约 280–320px），把 v6 原有“左侧频道列表”收敛为顶部房间切换器/可展开抽屉，避免永久四栏。
- 768–1279px：默认隐藏右侧详情，仅留“成员”“任务”可点击标签/抽屉；中央讨论区优先。
- 320–767px：房间标题紧凑两行、资源入口横向滚动；讨论占满主区域；底部输入可稳定使用；“成员/任务”抽屉访问，入口不能凭空消失。
- 房间分类：普通群聊与项目群聊两种；普通群聊没有关联项目时隐藏不适用的看板/文档/代码仓，不要跳错项目。
- 用户从项目卡片打开房间时保持项目上下文；从群聊跳看板/文档后可返回原房间。

## 四、建议的最小有效交互

1. 房间切换：分组搜索、未读标记、保存当前房间；不强迫用户先选项目。
2. 讨论：@提及必须是可选人/Agent 的选择列表（不能只插入固定文字）；Enter 发送、Shift+Enter 换行；引用消息与可编辑草稿。
3. 动态：过滤只影响可见信息，不删除内容；系统事件可折叠；保留日期/时间/发起方。
4. 任务：任务状态有具体标签；点开复用现有任务抽屉；消息转需求由用户确认标题、关联项目后才创建本机草稿。
5. Agent：单条运行状态卡用“待执行/执行中/待审核/已完成/失败”等UI演示状态；可展开当前步骤、关联代码或文档；不暗示实时执行。
6. 成员：人/Agent Tab；对“在线/忙碌/工作中”展示身份与状态区别；成员管理继续沿用 v6 弹窗。
7. 操作反馈：空消息、搜索零结果、项目无关联、创建失败（UI模拟）、撤销路径、键盘焦点与 Escape 关闭都要验收。

## 五、多角色对抗验收计划（实施阶段）

- **第一次使用**：进入后 5 秒内能定位讨论入口、房间名称、关联项目。
- **日常开发者**：通过 @Agent、关联需求和代码仓快捷入口，无须往返 3+ 页面。
- **项目经理**：从右栏任务点击到详情、变更负责人/状态在本地UI有可见反馈，不制造另一份任务副本。
- **公司管理员**：明确“成员与 Agent”身份边界，对权限与发布进行明确 UI 提示。
- **可访问性/安全红队**：恶意文本安全转义；回车输入法组合不误发；焦点可见；弹窗关闭返回；320/390/768/1024/1440/1664px 无文档级横向溢出；失败/空态可理解。
- **视觉红队**：防止彩色状态占据过多注意力、层层侧栏、密集小字、多个同级橙色按钮。
