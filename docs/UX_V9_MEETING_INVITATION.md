# AragonTeam v9 — 项目会议邀请与群聊入会闭环

日期：2026-10-23。工作分支：`jinngimk-lang-AT`，产品入口：`index.html`。本轮只做独立单文件前端 UI 原型，无真实账号服务、视频、音频、通知、Agent 调用或后端。

## 用户提出的问题

v8 会前弹窗的大段「谁会进入会议？」说明，不能直接完成邀请；选择开始会议后的操作反馈、群聊入会卡片可见性不直观。用户要求支持两条明确路径：指定邀请人进入会议，或把会议信息公布到群聊，由成员自主点击。

## v9 已落实的信息结构

一级导航继续仅智能体 / 项目 / 团队 / 个人；项目七项子菜单完全不变。会议只出现在 `智能体 → 群聊`。从项目房间点「开始演示会议」进入**会议发起弹窗**：

- 填写会议主题；二选一的邀请方式：
  - **发布到群聊（默认）**：单击「开始会议并发布」，发起人立即进入会议，群聊生成**入会卡片**；其他群成员不被默认算作受邀或实际参会者。群成员可从卡片点击「打开会议」，本地演示另提供「模拟成员自主加入」选择器，以便审稿人测试不同身份。
  - **邀请指定人员**：选择成员/Agent；单击「开始会议并邀请」，这些对象进入**待加入名单**，不会立即进会，也不会改变原有群聊成员列表；没有选择时禁止流程继续并提示用户。
- 进入会议后：舞台只显示**实际已入会**人员；「邀请参会者」可补充受邀名单；指定邀请模式下可再「发布到群聊」，让其他成员自行加入，且不可重复发布；可切换纪要/聊天/参会者视图。
- 从会议点「返回房间」只关闭会议窗口、不结束会议；当会议入会卡已发布，房间聊天列表自动滚动到卡片所在位置。会议卡有「打开会议」与「模拟成员自主加入」，不是任何人的自动入会。
- 明确二次确认结束会议；确认后清除进行中的入会卡，在房间保留一条**本机演示**结束消息。取消结束不改变会议状态。

## 交互与安全边界

- 人员属于群聊 ≠ 收到会议邀请 ≠ 已加入会议。全部计数由不同集合产生；Agent 未勾选不得自动出现。
- 本地仅模拟邀请状态与会议 UI，不会真的发送通知或消息，不会启动真实音视频；所有展示文案明确提示「演示」。
- 会议主题、人物与消息均按文本转义展示；恶意 HTML 不执行；取消准备不创建会议；未选邀请对象时不能发起定向邀请。
- 不接触真实业务系统或提交后端。数据仅供审查；本地 HTML 的跨刷新持久化仍需要用户在本机浏览器确认。
- 同一浏览器会话只模拟一个进行中的会议，切到其他房间不会自动结束当前会议或把其他房间成员误算到会。

## 验证

- 2026-10-23，`tests/test_v9.py` 使用 Chromium+Playwright、HTML 注入模式通过六种屏幕宽度：320 / 390 / 768 / 1024 / 1440 / 1664。涵盖默认发布→立即进入舞台→返回看到群聊卡片→主动加入→追加邀请→结束；定向邀请→待加入→会议内发布→返回卡片→结束；原「项目」页面回归；无浏览器脚本错误和整页横向溢出。
- `tests/test_v9_adversarial.py` 在 390/1440px 通过：取消不创建、空邀请提示、恶意标题不形成 HTML/JS、成员/Agent 不自动入会、补充邀请不改群聊成员、只有确认结束才清理活动会议。
- 图像人工抽查：会议准备弹窗、聊天入会卡片和会议舞台桌面/手机呈现；特别修复窄屏聊天卡片在可视区外的问题。截图保存在本地工作产物中，不添加大量 PNG 到 GitHub。
