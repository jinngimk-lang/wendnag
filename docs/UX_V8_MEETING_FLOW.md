# AragonTeam v8 — 会议交互模型与交付存档

日期：2026-10-23。目标文件：仓库根目录 `index.html`。工作分支：`jinngimk-lang-AT`。

## 本轮关键决定

**群聊成员 ≠ 会议受邀者 ≠ 真实参会者。** 进入已有「智能体 → 群聊」，点击「开始演示会议」应先弹出会前准备，不应自动把房间成员和 Agent 渲染为已入会。用户确认为主持人之后，会议才处于进行中；其余成员显示为待加入，Agent 只有在明确选中后才成为受邀者。整个功能只做前端 UI 演示，不使用麦克风、摄像头、网络会话、真正发送邀请或生成纪要。

## 交互路径

1. **会前准备**：可改会议标题；默认允许当前房间的其他人获得加入入口；Agent 需要单独勾选；取消不改变会议状态。
2. **确认发起**：只有发起人显示「已入会」。邀请名单上的其他人显示「待加入」；右侧按状态分组，不能把群聊人数冒充到会人数。
3. **追加邀请**：会议内「邀请参会者」仅改变当前会议的受邀者集合，不更改群聊的团队成员/Agent 名单；通过「模拟加入」明确更新 UI 状态。
4. **会议内工作**：右侧可切换示例 AI 纪要、会议聊天与参会者；纪要行动项的复选框须真实保持勾选；所有内容仅为本机演示。
5. **返回房间**：关闭会议窗口但保留进行中的会议状态；在房间内有返回入口。
6. **结束**：点击结束时二次确认；只有确认结束才清除当前会议。取消保留会议，防止误操作。
7. **状态边界**：会议标题、人员、聊天等用户输入统一按文本转义；未加入的受邀者不显示成在线参会者；界面不得暗示音频、视频、录制、共享或真实 Agent 正在运行。

## 红蓝队共同验收

- **新用户**：发起动作简单，准备、入会、邀请、结束含义一眼可分。
- **主持人/管理员**：只对会议名单做改动，返回和结束不同；邀请 Agent 必须显式。
- **参会者**：待加入、已入会、房间成员是三个不同状态。
- **窄屏设计**：会议舞台、参会者卡片、控制栏和纪要面板都必须真正位于可视区域，不以 DOM 元素存在作为充分验证。
- **安全/异常**：恶意 HTML 只按文字显示，操作不调用真实服务器；会话关联房间不存在时清理陈旧演示状态；界面已明确声明本地演示。

## 验证

2026-10-23 使用本地 Chromium + Playwright 的 HTML 注入模式复验 `tests/test_meeting_v8.py`：320、390、768、1024、1440、1664px 均通过，无整页横向溢出；`tests/test_meeting_adversarial_v8.py`：390/1440px 均通过，恶意 HTML 未执行、Agent 不自动入会、追加邀请不改变房间成员。另对 8 处内嵌脚本做 JS 语法解析，通过。

**明确未覆盖**：真实音视频、通知推送、真实身份与权限、设备访问、后端持久化，以及 file:// 刷新后所有演示状态的一致性。不应把纯前端 UI 原型称作已上线的会议产品。

## 继续开发约束

四个一级模块「智能体 / 项目 / 团队 / 个人」不新增，底部设置保留；项目七个二级菜单不变；只做前端交互。下轮先读本文件、`docs/UX_V7_GROUP_ROOM_ANALYSIS.md`、`docs/UX_V7_DELIVERY.md` 与根目录 `index.html`，fetch 当前分支 SHA 后做最小可逆改动；用多角色和多屏宽复验，并交付独立 HTML 给用户审核。
