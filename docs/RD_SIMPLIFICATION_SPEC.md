# AragonTeam 研发版简化改造 — 交互设计锚点与证据（2026-10-22）

## 需求与边界

- 目标仓库：`jinngimk-lang/wendnag`，分支 `jinngimk-lang-AT`，主文件 `index.html`。
- **项目二级菜单不得增加项**：项目管理 / 需求看板 / BUG看板 / 文档 / 代码仓 / 建议 / 版本。现有「团队」页面及一级导航也不能回退。
- 整体延续项目首图的深蓝字体、白底、橙色主操作、70px 一级导航和 246px 二级导航，默认浅色、按需展开详情，兼顾初次使用者、高频操作者、管理员和无障碍体验。
- 用户要求先提交**可审核的独立 HTML 原型**，后续经确认才有条件考虑接入真实后台。这里的 `index.html` 不代表生产系统，所有数据仍为本机演示。

## 设计映射

| 现有菜单 | 简化版交互 | 错误/安全设计 |
|---|---|---|
| 项目管理 | 原项目卡片保留，打开项目后进入当前选中项目需求看板 | 原项目功能回归；移动端宽度不溢出 |
| 需求看板 | 五列/列表切换，项目/状态/优先级/负责人筛选、重置、新建需求、右侧详情抽屉 | 允许无结果、Esc 关闭；抽屉中显示演示标签 |
| BUG看板 | 复用同一看板结构和筛选、BUG 详情及新建入口 | 数据按需求/BUG 明确区分，不把 BUG 误作需求 |
| 文档 | 文档目录与名称正文的查看、编辑、新建 | 本机保存，不声称线上协同 |
| 代码仓 | 仓库/分支概念入口与后端待接入说明 | 不捏造 Git/CI/PR 实时记录 |
| 建议 | 状态卡片、支持数、新建议 | 只记录本地操作 |
| 版本 | 简洁卡片、日期与摘要 | 所有条目标记为示例，非真实发布记录 |
| 智能体 → 我的智能体 | Agent 选择、MCP 与 Skill 分类过滤勾选、成员授权范围、使用策略、模板配置、测试与发布演示 | 发布并不真的开放给团队；无真实授权后端。MCP/Skill 要求至少各一项才可进入本地“已发布”状态 |
| 智能体 → 智能体任务 | 查看指派给 Agent 的需求/BUG 清单，点击进入相同任务详情 | 避免多个相互矛盾的任务详情入口 |

## 交互与反例验证

- 首次使用者：没有新增项目菜单；点击卡片即可进入详情；搜索筛选可重置；默认看板可定位阶段。
- 高频使用者：同一需求/BUG 既支持看板也支持表格，选择项目、优先级、负责人可以组合筛选。
- 管理员：主 Agent 最多一个、协作最多三个、主/协作互斥；草稿 Agent 不能完成演示指派；权限页声明服务端鉴权待实现。
- 审美与移动端：主要页面遵守留白、轻分割；320px 下一级 rail 与主区可用，项目卡片不撑爆页面；需求看板在窄屏局部横向滑动。
- 安全审查：内容插值统一 HTML 转义；不收集后台密码、不调用外部 API、不执行真实 Agent、不自动发送邮件或评论到服务器。

## 验证记录与缺口

- 静态 JS 语法检查通过；`test_rd_quick.py` 走查 Agent 指派、评论、任务状态、列表/看板、文档、Agent MCP/Skill、模板、团队和项目回归，无 JavaScript 页面异常。
- `test_multiview.py` 于 Chromium `page.set_content()` 注入模式下通过 320、390、768、1024、1440、1664px 六种屏宽与页面级无溢出检查。
- 原仓库的 `tests/team_smoke.py` 在原版上已通过。新版本仍保留团队模块，新的多屏回归重复覆盖团队入口和概览。
- 当前执行环境对浏览器实际访问 localhost / 任意 HTTPS 测试域阻拦（`ERR_BLOCKED_BY_ADMINISTRATOR`），**跨刷新 localStorage 持久化仍未实测**；用户应在 Chrome/Edge 打开 HTML 后进行最终本机验收。
- **上线缺口**：对接身份认证、权限校验、后端任务/Agent API、事务提交/撤销、并发冲突、审计日志、通知、文档/代码安全与运行结果反馈；本原型不能直接当成可上线后端产品。
