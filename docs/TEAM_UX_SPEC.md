# AragonTeam「团队」交互设计锚点与验收记录

工作分支：`jinngimk-lang-AT`；主要入口：仓库根目录 `index.html`；最近更新：2026-10-22。

## 目标与设计基准

沿用「项目」页面既有视觉体系：70px 一级图标导航、246px 二级侧栏、白色工作区、深蓝文字、橙色主操作；以用户提供的团队管理仪表盘参考图为结构线索，不以整张图片替代可编辑的 HTML。兼顾初次使用者（直接找到操作）、高频用户（搜索、筛选、列表）、管理员（团队成员和权限）及偏好简洁设计的用户（默认卡片页、不堆无用指标）。

## 已实现功能

- 一级导航保留：智能体、项目、团队、个人、设置。项目原始卡片与相关操作继续可用。
- 团队二级导航：团队管理、成员管理、角色权限、邀请记录、团队设置。
- 团队管理：8 个示例团队，实时推导团队总数、跨团队去重成员、关联项目、活跃团队；搜索团队名称、简介与成员；状态、类型、排序筛选；卡片／列表视图；显示已归档团队。
- 完整示例流程：创建团队（含名称校验和重名检查）、编辑资料、查看成员／项目／权限、添加已有成员、管理角色、记录／取消邀请、归档／恢复团队、JSON 导出、二次确认重置。
- 保护措施：最后一位管理员不能被降级或移除；归档可恢复；重置操作带确认；对外不可声称邀请邮件已经发送或服务端权限已经生效。
- 本地演示数据保存在 localStorage，默认 8 个团队、42 个去重成员、18 个去重关联项目和 6 个活跃团队；页面明显标注“演示数据 · 仅本机保存”。
- 手机窄屏：隐藏二级侧栏改成横向可滚动的团队子导航；适配 320–1664px；支持键盘焦点、Esc 关闭和基本弹窗 Tab 焦点循环、关闭后返回触发控件；减少动态效果。

## 验收事实与未验证项

在 Chromium + Playwright 的 HTML 注入模式下测试通过：初始数据、搜索 Research、空闲筛选、8 行列表、创建后 9 团队、邀请记录／取消、成员列表、最后管理员保护、归档恢复、原项目详情页及 320/390/768/1024/1440/1664px 无文档级横向溢出。测试文件：`tests/team_smoke.py`。复验：`python tests/team_smoke.py`（需安装 playwright 和 Chromium）。

当前自动化环境禁止 Chrome 导航 localhost（`ERR_BLOCKED_BY_ADMINISTRATOR`），因此 localStorage 跨刷新持久化和浏览器 JSON 下载尚未完成真实地址方式的自动化验证；需用户在 Chrome/Edge 打开本地 HTML 做最终验收。该界面是无后端的可交互设计原型，不是组织真实数据／邮件通知／服务器鉴权。

## 迭代守则

1. 用此文档恢复设计目标，修改前先回读 `index.html` 现有行为，不覆盖既有项目页。
2. 每轮保持完整单文件 HTML 交付用户验收；审查可用性、一致性、可访问性、响应式和误操作恢复。
3. 任何变更都跑团队筛选、建队、邀请、最后管理员保护、归档恢复及项目页回归；测试结论区分“已验证”与“待实机验证”。
4. 若接入真实服务端，应单独实现鉴权、细粒度角色授权、邀请邮件、审计日志、持久化存储、错误与空态处理，禁止依赖前端演示逻辑当作安全控制。
