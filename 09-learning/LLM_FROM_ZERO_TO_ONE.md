# 从 0 到 1 学懂大模型：白话高浓缩学习手册

> 目标：不是背术语，而是把“大模型为什么这样设计”串成一条完整因果链。  
> 主线：**文字 → token → 向量 → 概率 → 损失 → Attention → Transformer → 训练 → 推理 → 加速生成**

---

# 0. 先拿到整张地图

## 一句话先懂

大多数自回归大语言模型最核心的训练任务是：

**给定前面的 token，预测下一个 token 的概率分布。**

例如输入：

```text
今天天气很
```

模型内部不是先“想出一个词”，而是先得到类似：

```text
好   0.42
冷   0.21
热   0.14
差   0.07
...
```

然后再根据这个分布选择下一个 token。

完整流水线可以先记成：

```text
文字
 ↓ tokenizer
token id
 ↓ embedding
向量
 ↓ Transformer × N 层
上下文表示
 ↓ lm_head
logits
 ↓ softmax
概率分布
 ↓ sampling / argmax
下一个 token
```

训练时再增加：

```text
预测概率
 ↓ 与正确答案比较
Cross Entropy Loss
 ↓
反向传播
 ↓
更新参数
```

后面所有概念，本质上都是这条流水线里的零件。

---

# 1. Token：模型并不直接读“文字”

## 一句话先懂

**LLM 真正吃进去的是 token id，不是人类意义上的字和词。**

Tokenizer 会把文本切成若干 token，再映射成整数编号。

例如概念上：

```text
"我喜欢机器学习"
→ ["我", "喜欢", "机器", "学习"]
→ [125, 8301, 4217, 998]
```

这里 8301 > 125 没有语义上的“更大”。

它们只是词表中的索引。

## 为什么不直接按“词”切？

纯词级方案的问题：

- 新词太多；
- 生僻词覆盖困难；
- 中英文、代码、数字难统一。

纯字符方案的问题：

- 序列太长；
- 计算成本更高。

所以现代 tokenizer 通常采用子词或字节级的折中方案。

---

# 2. Embedding：把编号变成可计算的意义坐标

token id 本身没有语义。

模型有一张 embedding 表：

[
E \in \mathbb{R}^{V \times d}
]

其中：

- (V)：词表大小；
- (d)：隐藏维度。

token id = 125，本质上就是取：

[
x = E[125]
]

得到一个长度为 (d) 的向量。

## 白话理解

Embedding 可以理解成：

> 把每个 token 放到一个高维“意义空间”里。

不要把某一维硬解释成“动物”“性别”“情绪”。真实模型通常是分布式表示：很多维共同表达一个概念，一维也同时服务多个概念。

---

# 3. 为什么神经网络到处都是矩阵乘法

## 一句话先懂

**矩阵乘法可以理解成：把同一份信息换一个可学习的观察角度。**

例如：

[
y = xW
]

它不是凭空增加事实，而是把 (x) 中的信息重新组合成新的坐标表示。

Attention 里：

[
Q=xW_Q,\quad K=xW_K,\quad V=xW_V
]

就是让同一个 token 分别变成：

- “我想找什么”
- “别人如何找到我”
- “找到我后我给什么”

---

# 4. Logits：模型先打分，不是直接给概率

模型最后会为整个词表输出一组实数：

[
z=[2.1, 0.3, -1.2, \dots]
]

这些叫 logits。

Logit：

- 可以为负；
- 不需要总和为 1；
- 只是原始分数。

然后才经过 softmax 变成概率。

---

# 5. Softmax：把分数变成概率

[
p_i=\frac{e^{z_i}}{\sum_j e^{z_j}}
]

Softmax 做三件事：

1. 指数保证每项为正；
2. 除以总和后，总概率为 1；
3. 指数会放大较大的 logit，使高分 token 得到更高概率。

例如：

[
z=[2,1,0]
]

softmax 后约为：

[
p=[0.665,0.245,0.090]
]

最重要的是：

[
z_a>z_b \Rightarrow p_a>p_b
]

所以 softmax 不改变排序，只把“打分空间”转换成“概率空间”。

---

# 6. 为什么信息论里总出现 log

这是理解交叉熵最关键的一步。

假设一个事件发生概率为 (p)，我们想定义它的信息量 (I(p))。

希望满足两个直觉：

- 概率越小，事件发生时越意外，信息量越大；
- 两个独立事件一起发生时，信息量应该相加。

独立事件有：

[
P(A,B)=P(A)P(B)
]

所以我们希望：

[
I(pq)=I(p)+I(q)
]

而 log 正好把乘法变成加法：

[
\log(pq)=\log p+\log q
]

因为 (0<p\le1) 时 (log p\le0)，为了让信息量为正，定义：

[
\boxed{I(p)=-\log p}
]

于是：

[
p=1 \Rightarrow -\log1=0
]

必然发生的事情，没有“惊讶”。

而：

[
p=0.01 \Rightarrow -\log0.01\approx4.605
]

模型只给 1% 概率的事件真的发生了，代价很大。

---

# 7. 熵：真实世界自己有多不确定

若真实分布为 (p)：

[
\boxed{H(p)=-\sum_i p_i\log p_i}
]

也可以理解为：

[
H(p)=\mathbb{E}_{x\sim p}[-\log p(x)]
]

白话：

> 按真实分布 (p) 反复发生事件，平均每次有多“意外”。

---

# 8. 交叉熵：现实按 p 发生，模型却拿 q 去押

交叉熵：

[
\boxed{H(p,q)=-\sum_i p_i\log q_i}
]

这里一定要区分两个角色：

- 外面的 (p_i)：真实世界里事件出现多频繁；
- log 里面的 (q_i)：模型给这个事件多少概率。

因此：

[
\boxed{H(p,q)=\mathbb{E}_{x\sim p}[-\log q(x)]}
]

## 为什么是 log q，不是 log p？

训练时要回答的问题不是：

> “真实世界本身有多不确定？”

而是：

> “真实答案已经发生了，模型到底给它押了多少概率？”

所以惩罚的是模型 (q)。

---

# 9. One-hot 时，交叉熵为什么只剩 -log q_y

假设真实类别是第 2 类：

[
p=[0,1,0]
]

模型预测：

[
q=[0.1,0.7,0.2]
]

则：

[
H(p,q)
=
-[0\log0.1+1\log0.7+0\log0.2]
]

得到：

[
\boxed{L=-\log0.7}
]

所以语言模型训练可以高度浓缩成：

[
\boxed{
L=-\log P_\theta(\text{正确 token}\mid\text{上下文})
}
]

记住这句：

> **交叉熵训练，就是逼模型把更多概率质量放到正确 token 上。**

---

# 10. 交叉熵正反向为什么不同

通常：

[
H(p,q)\neq H(q,p)
]

因为：

[
H(p,q)=-\sum_i p_i\log q_i
]

而：

[
H(q,p)=-\sum_i q_i\log p_i
]

交换后，“谁代表现实”和“谁接受评分”都变了。

交叉熵还可以写成：

[
\boxed{H(p,q)=H(p)+D_{KL}(p\Vert q)}
]

因此它可以理解为：

> **真实世界不可避免的不确定性 + 模型预测偏离真实分布的额外代价。**

而 KL 本身也一般不对称：

[
D_{KL}(p\Vert q)\neq D_{KL}(q\Vert p)
]

---

# 11. 为什么 Softmax + Cross Entropy 配合特别自然

设：

[
q=\operatorname{softmax}(z)
]

真实标签为 one-hot (p)。

交叉熵对 logit 的梯度会化简成：

[
\boxed{\frac{\partial L}{\partial z_i}=q_i-p_i}
]

例如：

[
p=[0,1,0]
]

[
q=[0.1,0.7,0.2]
]

那么：

[
q-p=[0.1,-0.3,0.2]
]

直觉上：

- 错误类别概率高了 → 往下压；
- 正确类别概率低了 → 往上推。

这就是“损失”如何变成参数更新方向。

---

# 12. Attention 为什么出现

RNN 可以粗略画成：

```text
x1 → h1 → h2 → h3 → h4 → ...
```

后面位置想利用前面很远的信息，需要经过很多串行步骤。

Transformer 的关键变化是：

> **让每个 token 直接去检索其他 token。**

核心公式：

[
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}
\left(
\frac{QK^T}{\sqrt{d_k}}
\right)V
]

先不要背整式，只拆成两步：

[
QK^T
]

负责：

> **决定“应该看谁”。**

然后：

[
\text{attention weights}\times V
]

负责：

> **把被关注对象的信息拿回来。**

---

# 13. Q / K / V 为什么要拆开

最值得记住的是：

[
\boxed{Q=\text{我想找什么}}
]

[
\boxed{K=\text{别人应该如何找到我}}
]

[
\boxed{V=\text{找到我以后，我真正提供什么}}
]

例如：

```text
The animal didn't cross the street because it was too tired.
```

处理 `it` 时，可以粗略理解为：

- (Q_{it})：我要找“谁是我的先行词”；
- (K_{animal})：我是一个可能被代词指代的实体；
- (V_{animal})：我是 animal，并携带我的上下文语义。

模型先计算：

[
Q_{it}\cdot K_{animal}
]

如果分数高，就更多读取：

[
V_{animal}
]

## 为什么 K 和 V 不合并？

因为：

> “判断是否相关的特征”与“真正要传递的信息”并不一定相同。

像数据库：

```text
key      → value
user_123 → 用户完整资料
```

Key 用于寻址，Value 才是内容。

## 为什么 Q 和 K 也不合并？

若直接使用同一个向量空间做点积：

[
x_i^Tx_j=x_j^Tx_i
]

关系天然对称。

但语言关系很多是有方向的：

- 代词 → 先行词；
- 动词 → 宾语；
- 当前 token → 前文条件。

用不同投影：

[
Q_i=x_iW_Q,\qquad K_j=x_jW_K
]

一般可以得到有方向的匹配关系。

---

# 14. Multi-Head Attention：不是一套检索规则

每个 head 都有自己的：

[
W_Q^{(h)},W_K^{(h)},W_V^{(h)}
]

因此模型可以在多个关系子空间里并行检索。

不要把它机械理解成：

> “第 1 个头一定负责语法，第 2 个头一定负责指代。”

更准确的理解是：

> **多头让模型拥有多套不同的可学习关系视角，而不是把所有关系硬塞进一套相似度里。**

1. LLM 的基本训练任务是什么？  
   **根据上下文预测下一个 token 的概率。**

2. token id 本身有语义大小吗？  
   **没有，只是索引。**

3. (xW) 的直觉是什么？  
   **把同一信息投影到新的可学习表示空间。**

4. 为什么信息量使用 (-\log p)？  
   **因为小概率更意外，而且 log 能把独立概率的乘法变成信息量的加法。**

5. 为什么交叉熵是 (-\sum p\log q)？  
   **现实按 (p) 发生，但我们要惩罚模型 (q) 给真实事件的概率。**

6. one-hot 为什么只剩 (-\log q_y)？  
   **只有真实类别权重为 1，其余项全为 0。**

7. Q / K / V 分别是什么？  
   **Q=找什么，K=如何被找到，V=找到后给什么。**

8. Attention 本质在干什么？  
   **先算关系，再按关系加权读取信息。**
