# 0. 这份系统解决什么

前两轮研究解决了：

> 什么内容更容易产生流量、搜索、收藏、分享、回访和商业意图？

这一轮继续解决：

> 当我决定“要拍什么”以后，如何把它编译成一条真正可以交给 AI 视频模型执行的片子？

未来用户只需要给：

1. 产品 / 主题；
2. 平台；
3. 目标时长，例如 6s / 15s / 30s / 60s；
4. 目标：曝光 / 收藏 / 搜索 / 私信 / Demo / 品牌记忆；
5. 可用素材：人物、产品截图、Logo、真实 UI、场景参考；
6. 风格倾向（可选）。

系统必须自动输出：

- 主流量引擎 + 副引擎；
- Creative Thesis / 一句话创意；
- 故事欲望、阻碍、产品铰链、最终记忆点；
- Boldness Level；
- 人物 Bible；
- 场景 / 道具 / 色彩 / 光线 Bible；
- 精确到 0.5–1 秒级的事件时间线；
- 每秒台词 / 旁白 / 对话；
- 每镜头景别、角度、焦段、构图、运动、表演、灯光；
- 声音设计、音乐能量曲线、Foley、UI SFX；
- 转场 / J-cut / L-cut / Match Cut；
- 每个镜头单独的 AI Generation Packet；
- 模型路由；
- 产品/UI 保真与合成策略；
- 平台版本；
- A/B 版本；
- QA / 连续性 / 合规检查。

最终产物不是“一段 Prompt”，而是：

> **一个完整的 AI Director Compiler（AI 导演编译器）。**

---

# 1. 核心原则：先导演，再 Prompt

AI 视频最常见错误是：

> 想到一个画面 → 写很长 Prompt → 希望模型一次生成成片。

专业流程应该是：

**流量目标 → 戏剧目标 → 故事 Beat → 分镜 → 资产 Bible → Shot Packet → 单镜头生成 → 声音 → 合成剪辑 → QA → 平台版本**

原因很现实。

Runway Gen-4 官方把 5s / 10s 生成当作单 scene 使用，并明确不建议在一个短 clip 中同时塞很多场景、大动作和风格变化。

Google Flow / Veo、LTX、Higgsfield 的 2026 产品方向也都不是“巨型 Prompt”，而是：
- reference ingredients；
- storyboard；
- start/end frame；
- camera controls；
- character consistency；
- clip extension；
- node / flow；
- timeline assembly。

所以：

> **逐秒脚本属于整片导演层；生成模型收到的是“一个镜头一个 Prompt”。**

# 2. AI Director Compiler：八层架构

## L0 — Traffic Strategy / 流量策略

输入：
- Platform；
- Spike / Shelf / Series；
- 商业目标；
- 主流量引擎；
- 1–2 个副引擎。

必须回答：

### 为什么停下来？
Hook / result / conflict / visual surprise。

### 为什么继续？
悬念 / 证明 / 过程 / 故事推进。

### 为什么互动？
经验 / 投票 / 反例 / 评论命题。

### 为什么转发？
“太像你了” / “你应该知道” / “这个能帮你”。

### 为什么回来？
系列 / 挑战 / 进度 / 人物 / lore。

### 为什么相信？
实测 / UI / 来源 / 长期验证 / 主动承认限制。

---

## L1 — Creative Thesis / 创意命题

输出 7 个字段：

1. **Human desire**：人物现在想要什么？
2. **Obstacle**：什么具体摩擦挡住他？
3. **Cost**：如果没解决，损失什么？
4. **Hinge**：什么事件让产品进入？
5. **Proof**：哪个画面证明产品真做了事？
6. **Payoff**：人最终发生什么变化？
7. **Remembered idea**：观众只记一句，应该是什么？

例：

> 不是“LegalLens 是 AI 合同审查工具”。

而是：

> **“它把风险—依据—修改意见串成一条可以核验的链，把时间还给审合同的人。”**

---

## L2 — Story Compiler / 故事编译

系统根据时长和内容资产决定：

- Beat 数；
- Shot budget；
- Dialogue budget；
- Proof density；
- Silence / breathing room；
- Product arrival time；
- CTA time。

禁止机械平均分配时间。

切点只能由以下至少一个因素触发：

- new information；
- emotional change；
- physical action；
- gaze；
- proof；
- sound；
- spatial relation；
- rhythm release。

---

## L3 — Character / World Bible

AI 视频最怕“每一镜头重新抽卡”。

必须冻结：

### 人物
- 姓名 / 角色；
- 年龄段；
- 脸型；
- 发型；
- 发色；
- 服装；
- 鞋；
- 饰品；
- 身高体态；
- 表演基线；
- 声线。

### 场景
- 空间布局；
- 桌 / 门 / 窗 / 屏幕相对位置；
- 时间；
- 主光方向；
- 色温；
- 天气；
- 环境材质。

### 产品
- Logo；
- UI；
- 真实截图；
- 主色；
- 字体；
- 不能重画的可读文本。

### 声音
- 人物 voice；
- 产品 sonic motif；
- 环境底噪；
- 音乐风格。

Bible 的任务是：

> 让每一次生成都继承同一世界，而不是“每个镜头都像另一个广告”。

---

## L4 — Director / Cinematography

每一镜头必须回答：

1. Audience question；
2. Dramatic job；
3. Subject desire；
4. Obstacle；
5. Start state；
6. End state；
7. Viewer gaze；
8. Subject micro-action；
9. Framing；
10. Camera behavior；
11. Why camera moves；
12. Lighting logic；
13. Sound event；
14. Cut reason；
15. Handoff to next shot。

---

## L5 — AI Generation Packet

每镜头一个 Packet：

- Shot ID；
- Target duration；
- Aspect ratio；
- Reference assets；
- Immutable anchors；
- Start frame；
- Main action；
- Environment motion；
- Shot size / angle；
- Camera movement；
- Camera start/end；
- Movement reason；
- Lens / depth；
- Lighting；
- Style；
- Dialogue（若模型原生支持）；
- Sound intent；
- End frame；
- Handoff；
- Drift risks；
- Model route；
- Generation settings。

---

## L6 — Post / Sound / Composite

这里完成 AI 模型不应该承担的工作：

- 精确 UI；
- Logo；
- 真实文本；
- 字幕；
- 可核验数据；
- 复杂多层声音；
- 精确音画同步；
- J / L cut；
- time remap；
- speed ramp；
- masked transition；
- color continuity；
- brand end card。

---

## L7 — Critic / QA / A-B

最终检查：

- 每一镜头有工作吗？
- 可以删一镜头而不损失内容吗？
- 产品是不是太早进入？
- 人物身份漂了吗？
- 手 / 道具接触错了吗？
- UI 字变了吗？
- 光线方向变了吗？
- 运动方向穿帮吗？
- 强视觉是否抢掉产品记忆？
- Traffic Engine 是否真的被实现？
- 平台版本是否只是改尺寸？
- 这条可以 A/B 哪一个单变量？

# 3. Duration Compiler：输入时长，自动改变叙事

下面不是算法规则，而是制作默认值。

| 时长 | 默认镜头预算 | 能承载的故事 |
|---|---:|---|
| 6s | 1–2 | 单一 Hook + Proof / Visual Gag |
| 10s | 2–3 | Hook → Action → Payoff |
| 15s | 3–5 | Pressure → Hinge → Proof → Payoff |
| 20s | 4–6 | 增加真实过程 / 人类反应 |
| 30s | 6–9 | mini-story + 2–3 Proof beats |
| 45s | 8–12 | 情绪 / 实测 / 产品解释可并行 |
| 60s | 10–16 | 完整案例 + 多层证明 + 限制 |
| 90s | 14–22 | Context + objection + method + CTA |

## 3.1 6 秒

只有一个任务：

> **让我停下来，并马上相信一件事。**

适合：
- 强结果；
- before/after；
- 一个视觉笑点；
- 一次奇观；
- 一个状态变换。

不适合：
- 公司介绍；
- 三个功能；
- 两个人物完整对白；
- 长教程。

默认结构：

**0–1.5 Hook → 1.5–4.5 Proof → 4.5–6 Brand/Payoff**

---

## 3.2 10 秒

默认：

**Hook → One action → Visible payoff**

可做：
- 产品自证；
- 一次 AI task；
- 一个身份型承诺。

---

## 3.3 15 秒

非常适合品牌 / 产品广告。

默认：

- 0–3s：Pressure / Result Hook
- 3–5s：Hinge
- 5–11s：Proof
- 11–13.5s：Human payoff
- 13.5–15s：Brand attribution

注意：
品牌不一定最后才出现，但价值证明应早于大段产品介绍。

---

## 3.4 30 秒

可以形成完整 mini-story：

- Hook
- Human friction
- Product hinge
- Proof 1
- Proof 2
- Proof 3
- Payoff
- CTA / comment loop

30 秒是“流量内容 + 产品证明”相对平衡的甜点时长。

---

## 3.5 45–60 秒

可以增加：

- 真实实验；
- objection；
- 一次失败；
- 一个限制；
- 教程 step；
- 更完整前后变化；
- 评论命题。

60 秒不应该只是把 15 秒版本放慢。

---

# 4. 三种内容目标的时间权重

## Spike：爆发型

工作默认：

- Hook / surprise：15–25%
- tension / curiosity：20–30%
- proof / payoff：30–40%
- CTA / participation：5–15%

视觉：
- 更早 state change；
- 更强反差；
- 允许 B2–B3 镜头。

---

## Shelf：搜索/收藏型

默认：

- Problem definition：10–15%
- method / steps：45–60%
- proof：15–25%
- summary / save value：10–15%
- CTA：5%

视觉：
- readable；
- 清晰 UI；
- 稳定镜头；
- 少无意义炫技。

---

## Series：回访型

默认：

- Cold open：10–15%
- progress：20–30%
- complication：20–30%
- proof / result：20–25%
- cliffhanger / next episode：10–15%

视觉：
- 必须有 recurring motif；
- 固定开场 / 声音 / 人物动作；
- 结尾真正留下未完成任务。

---

# 5. Dialogue Compiler：逐秒台词不是硬塞字

“精确到秒”不等于机械写“第 1 秒 4 个字”。

正确流程：

1. 先写自然口语；
2. 给每一句设置目标时间窗；
3. TTS / 真人试读；
4. 得到实际音频长度；
5. 回填 Shot timing；
6. 只在最终剪辑里锁到 frame。

默认保留：
- 10–25% 纯视觉 / 呼吸 / silence；
- 情绪片可以更高；
- 教程口播可以更低。

## 对白表字段

| 字段 | 内容 |
|---|---|
| Timecode | 5.2–7.4s |
| Speaker | 人物A / VO / 数字伙伴 |
| Exact line | 最终台词 |
| Performance | fast / dry / whispered / relieved |
| Intention | convince / challenge / confess |
| Breath / pause | 句前/句后 |
| Subtitle | 是否逐字 / 关键词 |
| SFX overlap | 键盘 / click / silence |
| Visual sync | 哪个词对应哪个画面事件 |

ElevenLabs 2026 官方 Voice Design 支持把 age / persona / emotion / timbre / pacing / delivery 写入 voice prompt；Eleven v3 还可以用 whisper / sigh / laugh 等表演 tag。

因此声音导演也需要独立 Bible。

# 6. Traffic Engine → Film Grammar

## UTILITY / 实用

视觉：
- stable；
- overhead；
- screen capture；
- insert；
- macro detail；
- clean typography。

摄影：
- 35–50mm natural；
- locked / slow push；
- 重点信息用 rack focus / highlight。

剪辑：
- step by step；
- 少炫技；
- 高频 visual reset，但不能破坏阅读。

声音：
- 清晰 VO；
- 轻 UI clicks；
- music 低存在感。

核心：
> “让我学会 / 保存 / 以后能用。”

---

## PROOF / 证明

视觉：
- before/after；
- split comparison；
- timer；
- real input；
- real artifact；
- result insert。

摄影：
- macro result；
- rack focus；
- push-in at proof；
- controlled orbit only if product/object warrants。

声音：
- “click → result” sonic hinge；
- proof reveal 可以短 silence 后落 downbeat。

核心：
> “别信我，直接看。”

---

## EMOTION / 共鸣

视觉：
- close-up；
- imperfect framing；
- handheld；
- environmental pressure；
- micro-action。

摄影：
- snorricam / high angle / claustrophobic foreground；
- 慢推或突然 crash zoom 可制造痛苦/荒诞。

声音：
- room tone；
- exaggerated Foley；
- 一次 silence；
- 人声呼吸比音乐重要。

核心：
> “这就是我。”

---

## CURIOSITY / 反共识

视觉：
- hide/reveal；
- partial information；
- object POV；
- rack focus；
- unexpected scale。

摄影：
- push to discover；
- dolly zoom（只在认知反转有意义时）；
- impossible transition 可以用于 reveal。

声音：
- J-cut 先听到答案的一部分；
- abrupt silence；
- sound bridge。

核心：
> “等等，原来不是我以为的那样。”

---

## CULTURE / 热点/梗

视觉：
- recognizable visual grammar；
- meme timing；
- fast graphic match；
- social-native framing。

核心：
不是复制受保护素材，而是借：
- 叙事母题；
- 情绪结构；
- 参与规则；
- 圈层语言。

---

## PARTICIPATION / 参与

摄影：
- direct gaze；
- POV；
- reaction hold；
- 留出画面空间给评论/选项。

结尾：
不能只是“你怎么看”。

应该给明确任务：
- “把最离谱的 AI 翻车丢评论，我下一条实测。”
- “A/B 选一个，下一集只测票高的。”

---

## SERIALITY / 连载

必须固定：
- 开场动作；
- recurring shot；
- sonic motif；
- subtitle tag；
- character wardrobe logic；
- episode card。

结尾：
真正的 cliffhanger 是“任务没做完”，不是一句“下集更精彩”。

---

## TRUST / 信任

视觉：
- natural lighting；
- documentary；
- 真实桌面；
- 真实 UI；
- 长一点的 take；
- 允许小瑕疵。

声音：
- 人声自然；
- 少过度 sound-design；
- 可以保留吸气、停顿。

核心：
> “这真的发生过。”

# 7. Boldness Ladder：艺术大胆，但不镜头乱飞

## B0 — CLEAR

- locked；
- true UI；
- neutral lens；
- informational edit。

用在：
- Shelf；
- 关键 Proof；
- UI。

---

## B1 — SOCIAL NATIVE

- handheld；
- phone POV；
- jump cut；
- fast reframing；
- practical light；
- slightly imperfect frame。

用在：
- TikTok；
- 快手；
- 共鸣；
- BTS。

---

## B2 — CINEMATIC

- motivated dolly；
- crane；
- rack focus；
- graphic match；
- foreground reveal；
- light transition；
- controlled composition。

用在：
- 品牌广告；
- 人的情绪变化；
- 产品 hinge。

---

## B3 — AI-NATIVE IMPOSSIBLE

现实摄影昂贵，但 AI 很适合：

- camera 穿过合同纸；
- object POV；
- macro 一路推进进入 UI；
- frozen time；
- bullet time；
- impossible ceiling-to-screen move；
- office → data space continuous transition；
- through-object hidden cut；
- scale jump；
- environment folds / reconfigures。

原则：

> B3 必须发生在“剧情铰链”，不要全片连续 B3。

---

## B4 — SURREAL METAPHOR

把抽象摩擦物理化。

例：

### 合同压力
纸张不断从天花板掉落，逐渐把人物围住。

### 风险不可见
红色裂纹沿合同字行蔓延，但人物肉眼看不到；产品出现后裂纹变成结构化风险链。

### 信息噪声
几十个浮动窗口像交通堵塞围在人物周围。

### 时间被夺走
墙上钟的影子在桌面飞速伸长。

### Agent 带来秩序
杂乱纸张不是“飞走”，而像磁场一样排列成干净结构。

原则：
> 隐喻要把用户痛苦变得更容易理解，不是单纯怪。

| 360 Orbit | hero / reveal | 主体成为中心 | B2B勿泛滥 |
| FPV | 空间/速度 | 进入新世界 | 真实感下降 |
| Macro→Wide impossible | 产品细节→世界 | scale revelation | 易模型变形 |
| Whip-pan hidden cut | 快节奏 | 隐藏场景切换 | 运动过猛 |
| Match on action | 连贯 | 动作连续 | 需方向一致 |
| Graphic match | 高级转场 | 形状/意义联系 | 要预设计 |
| Sound bridge | 平滑/悬念 | 声音先行或延续 | 音频要精准 |
| Rack focus | Proof | 注意力从人→证据 | AI焦点可能漂 |
| Foreground reveal | Curiosity | 隐藏再揭示 | 前景需稳定 |
| Overhead collapse | 压力/秩序 | chaos→organization | 易像 MV |
| Handheld→Locked | 摩擦→解决 | 摄影稳定代表控制回来 | 非常适合 B2B |
| Cold→Warm light shift | 情绪转折 | 状态变化 | 不要过饱和 |
| Time freeze + moving hero | 决策/洞察 | 人从噪声中脱离 | 合成要求高 |
| Reverse motion | Undo / repair | “把混乱倒回去” | 物理逻辑需清楚 |

# 9. Camera Movement 必须有理由

错误：

> “cinematic, dramatic, 360 orbit, crane, zoom, handheld…”

正确：

> 她看到风险结果的一瞬间，镜头才开始 slow dolly in，从 medium shot 收紧到 close-up；运动不是为了“电影感”，而是观众的认知也同时收紧。

每个 camera move 写成：

**Start frame → Trigger → Path / Speed → End frame → Meaning**

例：

> Medium OTS，人物肩膀挡住一部分屏幕 → 她点开“风险依据” → camera 从肩后慢慢侧移并推进 → 最终屏幕与她的眼睛进入同一平面 → 从“工具”变成“她正在理解的证据”。

# 10. Lens / Framing 不是装饰

工作默认：

## 24mm
- 空间压力；
- 环境大于人物；
- 动感；
- AI-native movement。

## 35mm
- 真实工作场景；
- 纪录；
- 人与环境一起成立。

## 50mm
- 自然；
- 中性；
- 产品 + 人。

## 85mm
- 人物心理；
- 决定；
- 情绪 close-up。

## Macro
- 产品细节；
- 眼睛；
- 鼠标；
- 风险词；
- 手机提醒。

原则：

> 镜头从 24/35mm 逐步走到 50/85mm，可以自然表达“混乱世界 → 个人获得控制”。

# 11. Lighting Arc：让灯光也讲故事

不要每个镜头单独“cinematic lighting”。

先定义整片 light arc。

例：压力→控制

### Before
- overhead cool office；
- screen glow；
- hard mixed practical；
- 阴影杂。

### Hinge
- noise stops；
- UI / desk practical 成为视觉锚点。

### After
- warmer side light；
- softer contrast；
- background clutter reduced；
- negative space 增加。

光线不需要物理上突然“变魔法”。

通过：
- scene choice；
- exposure；
- color grade；
- shot direction
完成情绪变化。

# 12. Sound Director：声音不能最后再加

至少分六层：

1. Dialogue / VO
2. Room tone / ambience
3. Foley
4. UI / product SFX
5. Transition SFX
6. Music

## 12.1 Sound hinge

压力场景：

- notifications；
- keyboard；
- printer；
- phone；
- HVAC；
- page flipping。

产品铰链：

> 一次完整 silence。

然后只留下：
- 一个 click；
- 一个低频 pulse；
- UI 被组织起来的细微音色。

这通常比“音乐突然很燃”高级。

## 12.2 J / L cut

J-cut：
下一个场景声音先出现。

L-cut：
前一个声音延续到下一画面。

用途：
- 让 15 秒片不显得“每镜头都断”；
- 提前制造下一镜头好奇；
- 连接现实和 UI。

## 12.3 SFX 生成

ElevenLabs 官方建议：
复杂 SFX 序列最好拆开生成再混音。

所以：

不要生成：
> “键盘+纸+手机+门+低频+whoosh 全部一次完成。”

而要独立生成：
- paper shuffle；
- phone buzz；
- mechanical keyboard；
- UI confirm tick；
- office door；
- transition low whoosh。

# 14. Text-to-Video 与 Image-to-Video Prompt 要分开

## 14.1 Text-to-Video

可包含：

**Shot + subject + action + environment + lighting + camera + style**

例：

> Medium wide shot, a tired contract reviewer at a crowded desk, folders and printed contracts surrounding her. She searches through pages while a phone buzzes beside her. Cool late-office practical lighting. Slight handheld lateral drift, observational documentary realism, vertical 9:16.

---

## 14.2 Image-to-Video

如果 reference image 已经定义：
- 人；
- 构图；
- 场景；
- 光；

Prompt 应更集中于 Motion。

Runway 官方建议也是：

> image 提供视觉；text 重点描述 motion。

例：

> The woman stops flipping pages and looks toward the laptop. Her shoulders tense, then she exhales. The handheld camera slowly settles into a stable locked frame as she places both hands on the desk.

比重新描述：
> “a 23 year old woman, blue shirt…”
更有效。

# 19. 完整示例一：15s LegalLens「把时间还给人」

目标：
- 平台：抖音 / 视频号主版本；
- 主引擎：PROOF；
- 副引擎：EMOTION + TRUST；
- 类型：Spike + brand proof；
- Boldness：B3 一次；
- Remembered idea：**风险—依据—修改意见形成可核验链，人获得时间控制。**

## 19.1 Beat Map

| 时间 | Beat |
|---|---|
| 0–3s | Work pressure |
| 3–4.5s | surreal hinge |
| 4.5–10s | product proof |
| 10–13s | human payoff |
| 13–15s | brand attribution |

## 19.2 精确时间线

### 0.0–1.3s — SHOT 01 / 压力

视觉：
overhead-ish 24–28mm，桌面合同、便签、文件层层压住人物空间。

人物动作：
快速翻页，另一只手按太阳穴。

Camera：
轻 handheld 下沉。

声音：
纸、键盘、手机震动叠加。

VO：
> “30页合同。”

字幕只显示：
**30页合同**

目的：
EMOTION + problem recognition。

---

### 1.3–3.0s — SHOT 02 / 真正摩擦

85mm close-up。
眼睛从合同移到电脑，再看时间。

背景仍在响。

VO：
> “真正耗时间的，不是读完。”

句尾留 0.2s。

---

### 3.0–4.4s — SHOT 03 / B3 铰链

AI-native surreal shot。

一条红色风险线从合同字行中“实体化”，像发光细线沿桌面延伸。

Camera 贴近纸面 macro 跟随红线，最后**穿过合同纸**。

声音：
所有办公室噪声突然停止。
只留下低频 pulse。

VO：
> “是把风险、依据、修改意见——”

在“意见”前切入下镜。

注意：
红线只是隐喻，不替代真实 UI。

---

### 4.4–7.3s — SHOT 04 / 产品证明 1

通过纸张穿越，进入真实 LegalLens UI。

UI 必须真实合成。

35–50mm virtual camera / 2.5D。

视觉层级：
原条款 → 风险 → 法律依据。

VO：
> “串成一条能核验的链。”

Camera：
非常克制 slow push，只跟随信息层级。

SFX：
三个轻 click。

---

### 7.3–10.2s — SHOT 05 / 产品证明 2

真实 UI：
修改建议 / 风险列表 / Q&A。

用 mask highlight，不让模型生成文字。

人物手在现实桌面点击鼠标，可以与 UI match-on-action。

VO：
> “该看哪条，为什么，怎么改。”

这句每个分句对应一个视觉 reveal。

---

### 10.2–12.8s — SHOT 06 / 人的 Payoff

回现实。

同一办公室，但 camera 从轻 handheld 变完全稳定。

人物肩膀下降，合上最上面一叠文件，拿起外套。

光线稍暖，但不魔法变化。

音乐第一次打开空间。

VO：
> “工作有依据，时间才回到自己手里。”

---

### 12.8–15.0s — SHOT 07 / Brand

人物走向门口。

桌面前景虚焦，真实产品屏幕仍亮。

简洁 end card 合成：

**LegalLens 合约智审**  
**风险 · 依据 · 修改建议，可追溯**

VO：
> “LegalLens。”

不需要“立即下载/行业领先”等未经证实话术。

# 20. 完整示例二：30s「AI 最可怕的不是不会」

目标：
- 主引擎：EMOTION；
- 副引擎：PROOF + PARTICIPATION；
- 平台：抖音 / 快手 / TikTok；
- Boldness：B2；
- 内容任务：用 AI 真实翻车共鸣拉流量，再展示“可追溯证据”为什么重要。

## 核心 Hook

> **“AI最让我崩溃的不是它不会，是它错了还说得特别像真的。”**

## 时间线

### 0–2.5s
真人 direct-to-camera。
略 handheld。

台词：
> “AI最让我崩溃的，不是它不会。”

停顿。

### 2.5–4.5s
Crash zoom 到她的表情。

台词：
> “是它错了，还说得特别像真的。”

音效：
一个 dry UI error tick。

### 4.5–8s
演一个“普通通用 AI”回答场景。
不展示竞品 Logo。
答案中引用位置用模糊占位，不伪造真实法律结论。

人物微动作：
眼睛眯起，手停在鼠标上。

VO：
> “写得顺，不等于有依据。”

### 8–11s
人物回头看镜头：

> “所以我现在第一件事，不是问‘答案是什么’。”

### 11–13s
hard cut + silence：

> “我先问——证据在哪？”

字幕大字：
**证据在哪？**

### 13–19s
LegalLens 真实 UI proof：
条款 → 风险 → 依据来源。

VO：
> “把原条款、风险判断、依据放在同一条链上。”

### 19–23s
修改建议、可追溯结果。

台词：
> “建议我可以不同意，但至少我知道它为什么这么说。”

这是 TRUST。

### 23–26s
真人：

> “AI可以快。”

轻停顿。

> “但专业场景，先要能核。”

### 26–30s
Participation loop。

台词：
> “你遇到过最离谱的 AI 一本正经胡说是什么？丢评论，我下一条拿真实任务测。”

画面：
评论区视觉空间留白。
不要假评论截图。

这条的下一集天然由评论生成。

# 21. 完整示例三：60s Shelf「AI 合同审查到底该看什么」

目标：
- 主引擎：UTILITY；
- 副引擎：PROOF + TRUST；
- 平台：小红书 / B站 / 知乎 / 视频号；
- 类型：Shelf；

真实合同局部 + highlighter。

**“有风险”不等于“能处理”**

真实 UI 原文定位。

来源/法律依据区域。

修改建议。

Q&A / document context。

Shelf 内容 CTA 是“保存方法”，不是“点赞关注”。

然后输出完整制作包。

也就是说：

> **“时长”不是让脚本被截短，而是重新决定内容结构。**

# 29. 研究边界

1. 视频模型更新极快，model routing 应定期复核。
2. Shot budget / 时长结构是制作默认，不是平台算法。
3. AI 视频生成仍可能出现人物、手、物理、文本、连续性错误。
4. 真实产品 UI 和可验证信息应优先通过后期合成保真。
5. 电影摄影术语本身不创造好内容；戏剧目的优先。
6. “大胆”必须服务理解、情绪或证明。
7. 平台流量机制必须继续用第一方数据验证。
8. 涉及真人肖像、版权角色、金融/医疗、AIGC 标识等发布要求，制作前应重新核验。

# 30. 最终结论

前一份《自媒体平台流量机制地图》回答：

> **为什么用户愿意看、分享、保存、回来？**

这一份系统回答：

> **导演如何把这些“理由”变成时间中的画面、表演、镜头、声音和产品证据？**

最终最值得长期保持的原则是：

> **流量逻辑决定“为什么拍”；导演逻辑决定“什么时候让观众看到什么”；摄影决定“观众怎么感到它”；产品证明决定“观众为什么相信”；AI 生成模型只是执行镜头的工具。**

所以未来真正可复用的能力不是“一个 Veo Prompt”“一个 Runway Prompt”或“一个爆款模板”。

而是一套：

> **Traffic Engine → Creative Thesis → Duration Compiler → Story → Shot → Performance → Camera → Sound → Prompt → Composite → QA**

的完整编译系统。
